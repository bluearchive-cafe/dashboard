# 低性能设备交互体验优化设计

## 背景

当前控制面板使用 MDUI、背景图、半透明面板、毛玻璃、阴影和状态 Chip 组成界面。用户希望优先优化低性能设备上的交互体验，重点不是首屏加载速度，而是点击、切换、弹窗和保存流程的跟手感。

本次设计选择「默认全面轻量化」：不新增性能模式开关，不做设备能力自动判断，而是让所有设备默认使用更轻的视觉和交互策略。

## 目标

- 复选框、按钮和状态 Chip 的点击反馈更跟手。
- 保存设置时，控件禁用、加载态和恢复状态更稳定。
- 弹窗、Snackbar 和状态更新减少卡顿感。
- 页面视觉明显变轻，减少模糊、阴影和动画带来的渲染压力。
- 保留现有功能、后端 API 合约、主要布局、DOM ID 和可访问性行为。

## 非目标

- 不新增「性能模式」或用户偏好设置。
- 不根据 `deviceMemory`、`hardwareConcurrency` 等信号做自动分流。
- 不替换 MDUI 或重写组件体系。
- 不优先优化字体、背景图体积、网络请求链路或首屏加载时间。
- 不改变生产 API 地址、UID 规则或保存参数格式。

## 用户体验设计

页面仍保持当前的信息结构：顶部说明、三个资源项、保存/说明/复制/诊断按钮和页脚。视觉风格从「毛玻璃漂浮面板」调整为「轻量稳定表面」。

具体体验变化如下：

- 面板背景更接近实色或轻透明表面，减少毛玻璃质感。
- 阴影更短、更浅，主要依靠边框和色块表达层级。
- 背景图仍存在，但叠层更简单，避免持续触发昂贵的合成效果。
- 动画和过渡保持克制，`prefers-reduced-motion` 下进一步禁用非必要动态效果。
- 保存期间所有交互控件仍会禁用，避免重复提交；禁用和恢复过程需要避免重复写入相同状态。

## CSS 方案

### 基础视觉轻量化

调整 `src/css/control-panel.css` 中的主题变量和关键选择器：

- 降低 `--panel-bg`、`--surface-bg` 的透明材质依赖，使用更稳定的表面色。
- 收敛 `--hero-shadow`，减少大范围模糊阴影。
- 移除或大幅降低 `.page-overlay`、`.hero`、`.feature-list` 上的 `backdrop-filter`。
- 保留圆角和布局间距，避免界面从视觉上变成完全不同的产品。

### 暗色模式

暗色模式继续使用 MDUI 主题 token。暗色下同样减少阴影和模糊，避免在低性能设备上产生额外合成压力。

### 减少动态效果

保留并扩展 `@media (prefers-reduced-motion: reduce)`：

- 全局动画和过渡时间继续压低。
- 明确关闭面板和列表的毛玻璃效果。
- 不引入新的动画依赖。

## JavaScript 交互方案

### 控件禁用状态

优化 `src/modules/ui-state.js` 中的 `toggleInteractiveState(disabled)`：

- 如果元素当前 `disabled` 状态已经等于目标状态，则跳过写入。
- 保持 `INTERACTIVE_IDS` 不变，继续统一控制所有交互控件。
- 不改变保存期间「禁用所有交互控件」的安全行为。

这样可以减少保存流程中对 MDUI custom elements 的重复属性更新。

### 保存流程

保留 `src/modules/save-handler.js` 的现有流程：

1. 防止重复点击。
2. 设置保存按钮 loading。
3. 禁用交互控件。
4. 发起保存请求。
5. 显示成功 Snackbar 或错误 Dialog。
6. 恢复 loading 和交互状态。

实现时只做小范围调整，目标是减少同一状态的重复写入，避免改变错误处理、复制详情和 Snackbar 文案。

### 状态更新

保留 `src/modules/status-display.js` 的状态语义和 ARIA 公告行为。初始化时仍显示三个状态 Chip，并根据接口结果切换为可用、待维护或失败。

如果实现中发现状态更新有重复 DOM 写入，可以在不改变可访问性行为的前提下跳过无变化更新。

### 失败状态 Chip

失败状态 Chip 仍支持点击和键盘 Enter/Space 查看错误详情。若当前状态没有错误日志，不强制改变行为；是否增加「无错误时不弹窗」作为实现细节，由实现计划阶段根据现有 `dialog.js` 行为决定。

## 测试与验证

自动验证：

- `npm test`
- `npm run lint`
- `npm run build`

手动验证：

- 无 `uid`：交互控件保持禁用，阻塞 Dialog 正常显示。
- 无效 `uid`：交互控件保持禁用，阻塞 Dialog 正常显示。
- `?uid=ABCDEFGH`：状态和配置请求正常触发，三个状态 Chip 和复选框更新正常。
- 修改复选框并保存：请求期间所有交互控件禁用，完成后恢复。
- 保存成功和失败路径：Snackbar、错误 Dialog、复制详情行为正常。
- 帮助、复制链接、诊断信息和失败状态 Chip Dialog 正常。
- 暗色模式、窄屏和矮视口没有明显布局破坏。

## 范围控制

本设计聚焦于轻量化现有界面和交互路径。实现应优先选择小改动：CSS token、关键视觉属性、控件状态写入去重。若发现需要大规模重构、替换组件或新增设置入口，应先暂停并重新确认设计。
